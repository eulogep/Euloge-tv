## Synthèse par décision

### ALREADY_IMPLEMENTED

Fuse.js, Search, historique de recherche, filtres Explorer, Favorites, History, My List, Mobile V3, carrousel, Player, mini-player autoritaire, HLS natif/hls.js, fallback multi-source, EPG current/next/later, stale/unavailable, éligibilité, santé, validation externe, BFF, standalone, CI et E2E multi-navigateurs.

### ADOPT

- Autorisation admin côté serveur comme invariant d'architecture, après documentation et gate humain.
- AuditLog comme capacité du futur modèle, avant toute mutation.
- SourceCompliance comme modèle documentaire puis persistant, sans données TBCPL.

### ADAPT

- Découpage du futur admin en surfaces d'inspection read-only.
- Dashboard santé calculé uniquement à partir d'états MJTV mesurés.
- Représentation normalisée pays/langues/catégories.
- Redaction centralisée des URLs dans les surfaces admin.
- Observabilité progressive et sans détails sensibles.

### STUDY

Auth, CSRF, PostgreSQL/MongoDB/SQLite, repositories, inbox/modération, détection de doublons, rate limiting et worker de santé. Chaque sujet nécessite documentation et décision humaine avant code.

### ADOPT_LATER

Redis facultatif, Docker multi-stage non-root et Compose interne, après persistence/worker stabilisés.

### REJECT

Catalogue TBCPL, auto-remplacement de sources, publication GitHub directe, fetch distant non protégé, TLS désactivé, statuts de santé supposés, build permissif et refonte UI/Player/EPG.

## Ordre recommandé après gate humain

Gate Admin V1 obligatoire avant code : confirmer une surface interne uniquement, un garde serveur
fail-closed et les projections expurgées de Sources/Reports. Une exposition publique anonyme est
rejetée. `/admin/audit` reste hors V1 jusqu'à ce qu'une source réelle, une projection sûre et des
règles de rétention soient documentées et approuvées ; le futur modèle `AuditLog` ne doit pas être
introduit implicitement.

1. `feat/admin-readonly-v1` uniquement : `/admin`, synthèse, channels, sources, EPG, health et reports issus de données existantes avec projection sûre, sans mutation, audit log ni secret.
2. `docs/architecture/ADMIN_SECURITY.md` : frontière 401/403/admin, auth serveur future, cookies et CSRF.
3. `docs/architecture/DATA_MODEL_V2.md` puis `docs/architecture/ADR_DATABASE_V2.md`.
4. Nouveau gate humain avant toute abstraction de persistence.

Rollback de cette PR documentaire : revert des deux commits/docs, sans effet runtime, DB, cache, dépendance ou migration.
